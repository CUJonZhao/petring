## 本轮实现

- Feather 启动、IMU 和存储初始化成功后自动新建记录；脱离家庭 Wi-Fi 或关闭网页后继续写入。
- 保留原有分区，新增上半区 4 MiB 运动数据存储。20 Hz 下，一小时文件为 1,728,032 字节，另计文件系统开销。
- 保存原始六轴数据、时间、传感器温度、电压和简单活动分数/状态；约每秒批量同步，停止时保存尾批。
- 空间不足停止且不覆盖历史；异常重启保留未正常结束文件；校验损坏并提供原始文件恢复工具。
- `/records` 中文手机页面可停止/开始、列出历史、看整段曲线、下载完整 CSV 或二进制、确认后单条删除。
- 历史传输在停止采样后进行；网页原来的约 45 秒实时图继续保留，其按钮明确区分于完整历史。
- 手机与设备可以通过设备热点直接连接，不要求互联网。云端网站上传和蓝牙传输未实现；实机测试增加串口 `O` 关闭 Wi-Fi、`W` 恢复，用于验证真正无无线连接的记录。

## 验证及边界

- PlatformIO / Espressif32 7.0.1 / Arduino 2.0.17 编译通过，程序仍放得进原来的应用分区。
- 72,000 条合成样本通过实际 C++ 编码/缓冲后由独立 Python 工具读取，记录数、时间、符号与单位正确。
- 校验位损坏、截断尾部、重复时间戳、缓冲写失败、部分批次停止、旧分区地址/容量保持等主机检查通过。
- 浏览器模拟设备 API，手机/桌面布局及完整一小时曲线、72,000 行下载、断连、异常记录与删除取消流程通过。
- 下载同时核对服务端记录条数；截断传输报错，不显示为完整成功。
- 软件检查阶段用户选择稍后连接 USB；随后用户已接入并授权继续，现已备份、刷机和执行短测。
- 设备双 LittleFS 挂载、Wi-Fi 关闭后持续保存、CSV 与二进制逐条对比、正常停止文件在重启后不变、未停止文件重启后标记并恢复均通过。
- 原有 560 条电池日志逐行保留。当前 Wi-Fi 恢复、记录停止，所有测试文件仍保留在板上。
- 主机和实机结果分别记录；EN 重启不作为实际断电验证，USB 短测不作为一小时电池续航验证。
